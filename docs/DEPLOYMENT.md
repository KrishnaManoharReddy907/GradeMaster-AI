# Deploying GradeMaster

This guide puts GradeMaster online with three services:

| Piece | Service | Plan used here |
|---|---|---|
| Database + uploaded files (GridFS) | MongoDB Atlas | M0 (free, 512 MB) |
| API (FastAPI, Docker) | Render web service | Free |
| Frontend (static React build) | Render static site | Free |
| AI (grading, OCR mapping, feedback) | Google Gemini API | Free tier to start |
| Code execution | Judge0 CE public instance | No account |

Everything is defined in [`render.yaml`](../render.yaml) and [`backend/Dockerfile`](../backend/Dockerfile).
No secret is stored in the repository: you type them into the Render dashboard.

> **Cost notes.** All of the above can run at no cost for a demo or a small class.
> * Render free web services **sleep after ~15 minutes without traffic**. The first request after that takes
>   about a minute. For a real exam, either open the site a few minutes early or upgrade the API service to a paid
>   instance (check current pricing on render.com/pricing). Queued grading jobs are stored in MongoDB and resume on wake.
> * Atlas M0 holds 512 MB, including uploaded answer sheets. Upgrade if you store many scans.
> * Gemini free-tier limits are low; heavy use (whole classes of handwritten papers) may need billing enabled.
>   Check ai.google.dev/pricing before enabling it.
> * Google Cloud Vision is optional (Gemini reads handwriting without it). Vision needs a billing account.
> * The public Judge0 CE instance is rate-limited and shared. For large classes, use a paid Judge0 plan
>   (set `JUDGE0_API_URL`, `JUDGE0_API_KEY`, `JUDGE0_RAPIDAPI_HOST`) or self-host Judge0.

---

## 1. MongoDB Atlas (database)

1. Open https://www.mongodb.com/cloud/atlas/register and create an account.
2. **Create a cluster.** Choose **M0 / Free**. Pick a cloud region close to your users. Remember it; pick the
   same area for Render in step 3. Name it e.g. `grademaster`. Click **Create Deployment**.
3. **Create a database user.** In the dialog that appears (or **Security → Database Access → Add New Database User**):
   * Authentication: **Password**
   * Username: `grademaster_app`
   * Click **Autogenerate Secure Password**, then **Copy**. Keep it somewhere safe (a password manager).
   * Privileges: **Read and write to any database**
   * Click **Create Database User** / **Add User**.
4. **Allow network access.** **Security → Network Access → Add IP Address → Allow Access from Anywhere**
   (`0.0.0.0/0`) → **Confirm**.
   Render's free plan has no fixed outbound IP, so the database is protected by the strong password and TLS instead.
5. **Copy the connection string.** **Database → Connect → Drivers** (Python). Copy the string that looks like
   `mongodb+srv://grademaster_app:<db_password>@grademaster.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=grademaster`
   and replace `<db_password>` with the password from step 3.
   This full string is your **`MONGO_URI`**. Treat it like a password.

## 2. Gemini API key (AI features)

1. Open https://aistudio.google.com/apikey and sign in with a Google account.
2. Click **Create API key** (choose or create a Google Cloud project when asked) → **Copy**.
   This is your **`GEMINI_API_KEY`**.

Without it the app still works: MCQ and code execution are unaffected, handwritten answers get a provisional
keyword-only score flagged for teacher review, and code feedback falls back to rule-based hints.

*(Optional) Google Cloud Vision:* Google Cloud Console → **APIs & Services → Library → Cloud Vision API → Enable**
→ **Credentials → Create credentials → API key** → **Edit key → API restrictions → Restrict key → Cloud Vision API**
→ Save. This is **`GOOGLE_VISION_API_KEY`**.

## 3. Render (API + frontend)

1. Open https://render.com and **Sign up with GitHub**.
2. When GitHub asks, allow Render access to the **GradeMaster-AI** repository (you can limit access to just that repo).
3. In the Render dashboard click **New → Blueprint**.
4. Select the **GradeMaster-AI** repository and the branch to deploy
   (`feature/gradmaster-transformation` until it is merged, then `main`). Render reads `render.yaml` and shows two
   services: **grademaster-api** and **grademaster-web**.
5. Fill in the values Render asks for:

   | Key | Service | Value |
   |---|---|---|
   | `MONGO_URI` | api | the Atlas string from step 1.5 |
   | `GEMINI_API_KEY` | api | the key from step 2 (or leave empty) |
   | `GOOGLE_VISION_API_KEY` | api | optional; leave empty to use Gemini for OCR |
   | `CORS_ORIGINS` | api | `https://grademaster-web.onrender.com` |
   | `VITE_API_URL` | web | `https://grademaster-api.onrender.com` |

   `JWT_SECRET` and `BOOTSTRAP_TOKEN` are generated by Render automatically.
6. Click **Apply** / **Deploy Blueprint** and wait until both services show **Live** (the first build takes a few minutes).
7. **Check the URLs.** Open each service and look at the URL under its name. If Render added a suffix
   (e.g. `grademaster-api-ab12.onrender.com`), update the values:
   * **grademaster-api → Environment →** `CORS_ORIGINS` = the real frontend URL → **Save, rebuild, and deploy**.
   * **grademaster-web → Environment →** `VITE_API_URL` = the real API URL → **Save** → **Manual Deploy → Clear build cache & deploy**
     (the API URL is baked into the frontend at build time).

## 4. First sign-in

1. In Render open **grademaster-api → Environment** and reveal/copy **`BOOTSTRAP_TOKEN`**.
2. Open the frontend URL and go to **`/setup`**. Enter your name, email, a strong password and the setup token.
   This creates the only administrator; the page locks itself afterwards.
3. Sign in, then add departments, sections and subjects (**Academics**), create or approve teachers
   (**People / Approvals**) and assign them (**Teaching assignments**).

## 5. Verify the deployment

**AI check:** sign in as admin and open **Overview → System health**. The **Gemini AI** row makes a real test call.
If it says *Not working*, the red text underneath is the exact reason (e.g. missing key, invalid key, API not
enabled). Fix it in **grademaster-api → Environment → `GEMINI_API_KEY`** (paste only the key, no quotes or spaces),
save, and let the service redeploy. Submissions graded during an outage can then be re-scored with
**Re-run AI scoring** (handwritten) or **Re-run evaluation** (coding).

Run these from any terminal (replace the URLs):

```bash
curl https://grademaster-api.onrender.com/api/health          # {"status":"ok"}
curl -I https://grademaster-api.onrender.com/api/docs         # 404 (docs are off in production)
curl -I https://grademaster-api.onrender.com/api/health | grep -i strict-transport   # HSTS header present
```

In the browser: sign in as admin, create a teacher, publish a short MCQ test, take it as a student, and check the
result. Then try a coding question (Judge0) and a handwritten upload (Gemini) once.

## 6. Existing data (optional, needs owner approval)

The deployment above starts with an **empty** database. To bring over the data from the original local
`grademaster` database instead:

1. Take a fresh backup first (see [RECOVERY_GUIDE.md](../RECOVERY_GUIDE.md)).
2. Copy it to Atlas with the MongoDB Database Tools:
   ```bash
   mongodump --uri "mongodb://localhost:27017" --db grademaster --out ./gm-dump
   mongorestore --uri "<MONGO_URI>" --nsInclude "grademaster.*" ./gm-dump
   ```
3. On first start the API applies the schema migrations (indexes, user flags, score backfills). Migration 001 moves
   duplicate submissions into `submission_duplicates_archive` rather than deleting them.

Answer-sheet files uploaded by the **old** version live on the local disk (`backend/uploads/`), not in MongoDB, so
they are not copied by these commands. Their transcribed text and grades are.

## 7. Updating and rolling back

* **Automatic deploys are on** (`autoDeploy: true`): every push to the deployed branch (`main`) rebuilds and redeploys
  both services. No action is needed after a commit; watch progress under each service's **Events**.
* Check the branch once: **Render → each service → Settings → Build & Deploy → Branch** should be `main` and
  **Auto-Deploy** should be **On Commit**. (If you created the services from the feature branch, switch the branch to
  `main` there, or under **Blueprints → grademaster → Settings**.)
* Deploy by hand any time with **Manual Deploy → Deploy latest commit**.
* Roll back with **Events → (previous deploy) → Rollback**.
* Rotating `JWT_SECRET` signs everyone out. Rotating the Atlas password requires updating `MONGO_URI`.

## Environment reference

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `APP_ENV` | yes (prod) | `development` | `production` enables HSTS and hides API docs |
| `MONGO_URI` | yes | `mongodb://localhost:27017` | MongoDB connection string |
| `MONGO_DB_NAME` | no | `grademaster` | Database name |
| `JWT_SECRET` | yes | none | ≥ 32 random characters; the app refuses to start otherwise |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | no | `120` | Session length |
| `BOOTSTRAP_TOKEN` | recommended | none | Required on `/setup` when set |
| `CORS_ORIGINS` | yes (prod) | localhost | Comma-separated frontend origins |
| `TRUSTED_PROXY_HOPS` | prod | `0` | Proxies in front of the API (Render: 1) for client-IP rate limiting |
| `ENABLE_API_DOCS` | no | dev on / prod off | Force `/api/docs` on or off |
| `RATE_LIMIT_ENABLED` | no | `true` | In-memory per-IP limits (login, signup, uploads, AI) |
| `GEMINI_API_KEY` | recommended | none | AI grading, explanations, OCR mapping, feedback, question drafts |
| `GEMINI_MODEL` | no | `gemini-2.5-flash` | Gemini model id |
| `LLM_PROVIDER` | no | `gemini` | `gemini`, `ollama` or `none` |
| `GOOGLE_VISION_API_KEY` | no | none | Primary OCR; Gemini vision is the fallback |
| `JUDGE0_API_URL` | no | `https://ce.judge0.com` | Code execution endpoint |
| `JUDGE0_API_KEY`, `JUDGE0_RAPIDAPI_HOST` | no | none | For RapidAPI-hosted Judge0 |
| `MAX_UPLOAD_MB`, `MAX_PDF_PAGES` | no | `20`, `20` | Upload limits |
| `VITE_API_URL` | yes (frontend build) | `http://localhost:8000` | API base URL baked into the frontend |

## Security notes

* The API runs as a non-root user in the container, one process (the job worker and rate limiter are per-process).
  Scale vertically, or move rate limiting to a shared store before running several instances.
* Security headers: API sends `nosniff`, `X-Frame-Options: DENY`, a locked-down CSP and HSTS in production. The
  frontend ships a strict CSP (no inline or third-party scripts; Monaco is bundled, not loaded from a CDN).
* Passwords are bcrypt-hashed; tokens carry a version that is bumped on password change or deactivation.
